# PatchGraph-QA

**A verifiable question-answer benchmark over real repository code graphs, anchored on the
symbols that real bug fixes touched.**

Coding agents in the [Gemma 4 Developer Agent Competition](https://www.kaggle.com/competitions/gemma-4-developer-agent)
are given code graphs (`get_code_neighbors`, `get_code_subgraph`) to navigate large repos.
PatchGraph-QA asks a simpler, measurable question first: *can a model actually reason over
those graphs?* Every question (callers, callees, later k-hop, paths, impact sets) is generated
from the provided graphs and answered exactly by NetworkX, so scoring needs no human labels.
Questions are anchored on the functions each gold patch changes, which keeps them relevant to
real repair work rather than random graph trivia.

Target: the **Best New Resource** award of the
[paper track](https://www.kaggle.com/competitions/gemma-4-developer-agent-paper)
(writeup due **Nov 12, 2026, 23:59 UTC = 17:59 CST**).

## What is in this repo

| Path | Purpose |
|---|---|
| `src/patchgraph_qa/io.py` | Find the data (Kaggle mounts, Colab, `PGQA_DATA_DIR`), load `tasks.jsonl`, node-link graphs (`edges` or `links`), `.npz` embeddings. Missing fields are reported, not invented. |
| `src/patchgraph_qa/patch_parse.py` | Parse unified diffs into files, hunks and old/new line numbers; map changed lines to graph symbols with a recorded method (`span` > `source` > `name` > `text`). |
| `src/patchgraph_qa/stats.py` | Graph stats: nodes, edges, edge types, node schema, test nodes, async nodes, possible async gaps, isolates, degrees; embedding shape/dtype/alignment. |
| `src/patchgraph_qa/questions.py` | `QAItem` schema, `callers` / `callees` templates, adjacency-list encoding, set scoring. |
| `notebooks/01_explore_graphs.ipynb` | Colab/Kaggle notebook: download (Colab), load, stats, coverage, plots, checklist. Generated by `scripts/build_notebook.py`. |
| `tests/` | pytest on tiny synthetic fixtures (no real data needed), including running the notebook's analysis cells. |

### QA item schema

```json
{"id": "16-hex sha1", "task_id": "fastapi_11194", "template": "callers",
 "encoding": "adjacency_list", "question": "...", "answer": ["a.b.c", "..."],
 "difficulty_hops": 1, "anchor_symbols": ["fastapi.routing.x"],
 "meta": {"edge_types": ["calls"], "answer_format": "set", "context_edges": 12,
          "context_truncated": false}}
```

`meta` records provenance. Design rules: an item is **refused** (not emitted) if its context
cannot support the full answer; empty answers are skipped by default because "no callers" may
be a graph defect rather than a fact. Answers are correct *with respect to the provided graph*.

## Quick start (local)

```bash
python -m venv .venv && source .venv/bin/activate
make install     # pip install -e ".[dev,notebook]"
make test        # pytest, synthetic fixtures only
make lint        # ruff check + ruff format --check
make notebook    # regenerate the notebook from scripts/build_notebook.py
make zip         # git archive -> ../patchgraph-qa-day1.zip
```

## Getting the data

You must have joined the competition and accepted its rules. **Never commit or share the data**
(the rules forbid redistributing it; `data/` is git-ignored).

**Option A: Kaggle notebook (easiest, nothing to download).**
New notebook → *Add Input* → Competition → `gemma-4-developer-agent`. The notebook auto-detects
`/kaggle/input/gemma-4-developer-agent/` and `/kaggle/input/competitions/gemma-4-developer-agent/`
(which one Kaggle uses is unverified). To install this package there, upload
`patchgraph-qa-day3.zip` (or any `patchgraph-qa-day*.zip`) as a private Kaggle Dataset and add it as an input too.

**Option B: Google Colab.**
1. kaggle.com → Settings → **API Tokens** → create a token.
2. In Colab, key icon → add secret **`KAGGLE_API_TOKEN`** with the token, and enable notebook access.
3. Put `patchgraph-qa-day3.zip` (or any `patchgraph-qa-day*.zip`) in Google Drive → My Drive (up to 3 folders deep; if there are
   several `patchgraph-qa-day1*.zip`, the most recently modified one is used). Open
   `notebooks/01_explore_graphs.ipynb` and run all cells: it mounts Drive, finds and extracts the
   zip (browser upload is only a last-resort fallback), and adds `src/` to `sys.path` so no
   runtime restart is needed. If the Drive mount fails, the cell prints what to do and stops
   (browser upload only with `USE_UPLOAD = True`). Downloads pause between files and back off on
   HTTP 429; re-run the download cell until it reports nothing missing. It installs `kaggle>=2.2` and downloads **only** `tasks.jsonl`, `graphs/` and
   `embeddings/`, one file at a time (the 22 GB snapshots and wheels are skipped).
   Fallbacks: legacy secrets `KAGGLE_USERNAME` + `KAGGLE_KEY`, or uploading `kaggle.json`.

Do not `import kaggle` in Python while relying on `KAGGLE_API_TOKEN`: the library removes the
variable on import ([kaggle-cli#882](https://github.com/Kaggle/kaggle-cli/issues/882)). The
notebook only uses `!kaggle ...` shell calls.

**Option C: your own machine.** `pip install "kaggle>=2.2"`, `export KAGGLE_API_TOKEN=...`,
then `kaggle competitions download gemma-4-developer-agent -f tasks.jsonl -p data` (and the same
per file for `graphs/<repo>_<base_commit>.json`, `embeddings/<repo>_<base_commit>.npz`; get the
list with `patchgraph_qa.io.download_names(tasks)`). Point the code at it with
`PGQA_DATA_DIR=data`.

## Verified on the real data (Oct 17, 2026, kaggle CLI 2.0.2)

- `tasks.jsonl` has 129 tasks (e.g. `fastapi_15661`), covering 127 unique commits.
- Graphs and embeddings are named by **repo + commit**, not task id:
  `graphs/<repo_short>_<base_commit>.json`, `embeddings/<repo_short>_<base_commit>.npz`
  (`repo_short` = last part of `task.repo`, lowercased). 127 embedding files exist.
  `download -f graphs/<instance_id>.json` returns 404.
- `kaggle competitions files` output is paged/incomplete (195 of ~254 with `--page-size 1000`),
  so file names are built from `tasks.jsonl` instead.
